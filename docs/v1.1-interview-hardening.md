# v1.1 面试问题驱动验证说明

## 已实现

- `GET /trace/llm/{request_id}`：返回一次请求的 LLM 调用明细、输入/输出/总 Token、延迟和可选成本。
- `GET /trace/llm`：查看最近的 LLM 观测记录。
- `/chat` 响应中的 `llm_usage`：便于直接展示单请求证据。
- `/metrics` 中的 `coordexa_llm_*`：Prometheus 采集调用数、Token、缺失 usage、延迟和活跃调用。
- provider 没有返回 `usage` 时只标记 `usage_available=false`，不根据字符数伪造 Token。
- Agent 空文本自动重试一次；多 Agent 结果包含 `degraded` 和 `degraded_agents`。
- 上下文按提示、记忆、检索结果分区预算；Chunk 支持大小、overlap 和超长句硬切配置。

## 参数

价格不写入代码。只有同时设置以下两个环境变量才会产生 `estimated_cost_usd`：

```text
COORDEXA_INPUT_COST_PER_1M=
COORDEXA_OUTPUT_COST_PER_1M=
```

上下文与切片实验参数见 `.env.example`。默认 Chunk 设置仍为 500 字、0 overlap，以便与 v1.0 基线可比。

## 评测命令

确定性测试在容器内运行：

```bash
docker compose --profile test run --rm tests
```

当前分支基线为 70 条测试。在线稳定性扩展集：

```bash
python scripts/run_benchmark.py \
  --base-url http://localhost:8200 \
  --cases evaluation/fixtures/benchmark_cases_v2.json \
  --top-k 3 \
  --output evaluation/results/coordexa_v2_benchmark.json
```

v2 由 12 条对话和 6 条检索标注样本重复 4 轮组成，目标量为 48 条对话请求和 24 条检索请求；重复执行用于观察真实 API 链路稳定性，不宣称生产准确率。
